# 화면 목록 & 플로우

## 핵심 플로우 (Happy Path)
```
랜딩 → 이벤트 상세 → [대기열] → 좌석 선택 → 주문 확인 → [결제 처리중] → 결과
```

## 화면 정의

| ID | 화면 | 목적 | 핵심 상태 |
|----|------|------|-----------|
| S0 | 랜딩/이벤트 목록 | 오픈 예정·진행중 이벤트 노출 | 오픈전/오픈중/매진 |
| S1 | 이벤트 상세 | 일정·가격·"예매하기" CTA | 오픈 카운트다운 |
| S2 | **대기열** | 내 순번·예상 대기시간·진행바 | 대기중 / 입장가능 |
| S3 | 좌석/등급 선택 | 좌석 점유(hold), 잔여 표시 | 선택중 / 점유성공 / 점유실패 |
| S4 | 주문 확인 | 수량·금액·약관 | 검증 |
| S5 | **결제 처리중** | 비동기 처리 대기(폴링/WS) | 처리중 / 성공 / 실패 |
| S6 | 결과 | 예매번호 또는 실패 사유 | 성공 / 매진실패 / 시간초과 |

## 상태가 중요한 화면 (트래픽 전략이 드러나는 곳)

### S2 대기열
- 대기중: "앞에 N명, 예상 M분" + 진행바 + 이탈 경고
- 입장가능: "지금 입장하세요" CTA, 토큰 만료 카운트다운
- 폴링 주기 2~3초, 입장 토큰 만료 시 재대기 안내

### S5 결제 처리중
- 예매가 Kafka로 비동기 처리되므로 "처리중" 상태가 실제로 존재
- 폴링 또는 WebSocket으로 결과 통지
- 타임아웃/실패 시 명확한 안내와 재시도 경로
